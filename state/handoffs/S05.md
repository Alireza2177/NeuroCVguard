## Scope delivered

REQ-S05 and AT-S05-01 through AT-S05-10 are implemented and exercised.
S05.A constructs one canonically ordered record per participant, protects S03
transitive components, delegates to StratifiedGroupKFold and expands to all
observations. S05.B delegates site/phase holdout to LeaveOneGroupOut, refusing
crossing participants/components, incomplete domains and invalid actual training.
S05.C independently audits generated plans, records feasible warnings and exact
support, binds stable digests/IDs and writes explicit sensitive local artifacts.
No seed search, row dropping, relabeling, fold reduction or splitter fallback occurs.

New application file: `src/neurocvguard/splitting.py`. Modified application files:
`__init__.py` (lazy make_splits), `models.py` (runtime generation_report and write),
`serialization.py` (explicit runtime-field exclusion), `config.py` (updated scheme docstring), `errors.py` (PlanningError),
`io.py` (sensitive writers), `rules.py` and `_projection.py` (three stable plan
rules and fixed public wording). New tests: `tests/test_generation.py`,
`test_domain_generation.py` and `test_plan_exports.py`. New guide:
`docs/split_generation.md`; README, assistance, package description and S05
QA/project records were updated. Evidence/helpers are under `qa/evidence/S05/`.
Version 0.1.0 and runtime dependencies are unchanged. Existing specifications,
schemas, fixtures, predecessor tests and earlier evidence are preserved.

The user selected S05 only. S04's implemented auditor supplies its dependency;
human acceptance is still pending and no earlier acceptance is inferred. S02

## Scientific and privacy review

[review.md](../../qa/evidence/S05/review.md) records implementation-AI review, not
independent or human acceptance. Participant multiplicity does not affect the
stratification input; mixed-class families keep per-person labels. Protected
relationships remain intact. Domain objectives require domain separation;
repeated observations or shared known sites are not universally leakage.

The independent S04 audit blocks invalid generated training/separation/coverage,
retaining all scoped findings and actual class supports. Missing test classes are
warnings, not invented scores. Class-component counts are only a necessary
condition for class-complete test folds, never a promise of exact stratification.
Unknown upstream fitting remains unassessable and report execution remains
partial on successful planning. No model fitting or scientific-validity certificate
was added.

The strict plan schema is unchanged. generation_report is a nonserialized runtime
AuditReport with dependency versions and requested settings; reloading/replacing
a plan cannot recreate or authenticate that history. Public projection removes
raw identities/open evidence. Explicit plan.write exports identity-bearing
plan.json and assignments.tsv, a sensitivity notice, and captured
generation.private.json when available. PlanningError.report can be saved as
separate rejected-plan.private.json; no rejected plan is returned as usable.

Writer tests verify conflict preflight, exclusive default reservations, explicit
overwrite, preservation of unrelated files, competing-writer behavior and staging
failure. Each replacement is atomic; the whole bundle is not a filesystem
transaction. An I/O failure during replacement can leave partial outputs and
raises an actionable error. Sensitivity notices are not an access-control guarantee.

## Deviations and decisions

No normative contract, rule, fixture or acceptance requirement changed and no
contract-conflict ADR was needed. Runtime report metadata is explicitly excluded
from canonical serialization instead of extending the strict external plan schema.
It is exported through the existing AuditReport contract in a separate private file.

The installed sklearn has no typing metadata. A documented mypy import override
is limited to sklearn/sklearn.*; NeuroCVguard functions retain strict checking.
No new dependency or broad type-check suppression was introduced. The stale
SplitScheme docstring was updated after functional verification; no behavior changed.

The initial export tests expected the wrong existing exception class and placed
a seed-range assertion after config construction, where validation had already
failed. They now assert the actual strict boundaries; no input rule was weakened.
Import/format/line-length issues were corrected, including one probe message.
The first ordinary install could not fetch hatchling in the restricted environment;
the authorized retry passed. Failed logs are retained. No test was deleted or
skipped, and no unresolved S05 implementation-check failure is known.
