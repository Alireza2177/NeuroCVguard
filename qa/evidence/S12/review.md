# S12 implementing-agent review

Reviewed by the implementing Codex agent on 2026-09-26. This is not an independent
AI review or human scientific acceptance. No subagents were used.

Opened instruction sources are recorded in `instruction_loading.md`. The user
authorized S12 and approved ADR-S12-001; no other schema change was authorized.
`check_context.py` verifies that removing the optional context restores exactly
the two pre-stage normative schemas and that packaged copies match. Existing
records without context remain readable; extended standalone and embedded records
are validated and contradictory counts/class definitions are refused.

Inspected comparison, input preflight, eligibility, evaluation accumulation,
projection, rules, CLI and report-template changes. Comparison never fits or ranks
designs. Signed A-minus-B values require matching recorded identities, class
definitions and participant units; incomplete and undefined results retain nulls.
Class support follows whole-metric suppression; linked differences cannot expose
hidden cells. Raw digests, memberships and feature names stay out of public
comparison context. Class labels use existing projection and HTML uses escaping.

Diagnostic eligibility retains original failed split audit findings. Only outer
participant/component overlap without extra independence columns is eligible;
observation overlap, unknown membership, class failures, domain/family constraints,
invalid inner folds, repeats and incomplete CV remain guarded before fitting.
Clean ordinary plans are not mislabeled by an unused diagnostic flag. Inner fits
remain restricted to outer training and participant-disjoint inner partitions.
Raw held-out observation probabilities are pooled once per participant; the
unequal-visit oracle distinguishes this from incorrect averaging of fold means.
The original split-audit implementation is unchanged. No score ordering or
effect-size assumption is used by diagnostic tests.

Default and detailed HTML escape supplied values. Diagnostic CLI/HTML warning and
public JSON validity evidence survive rerendering. Text explains that participant
aggregation cannot repair training leakage and that design differences are
descriptive, not a causal amount of leakage. Model context uses only recorded C
values and the prescribed family; complete settings require original config.

All new data are existing documented fictitious fixtures or handwritten synthetic
contract/oracle inputs. They are not patient data or reported benchmark results.
Runtime journeys execute outside the repository cwd, check module/console/API
parity, input refusal, output preservation and incomplete comparisons, and clean
only their own temporary directories. No network call, public upload, Git push,
telemetry, dynamic user code or estimator deserialization was introduced.

Failed checks remain in evidence: an initial mismatch test used the unchanged
positive class; two report assertions used platform-default decoding for UTF-8;
Ruff found import ordering, long strings and mixed line endings. Assertions were
corrected without dropping tests or weakening behavior. Commands and subsequent
results are recorded in `commands.md`. The existing pre-S12 scope guard now accepts
the explicitly enabled option on a valid ordinary plan, with dedicated S12 tests
retaining default-off and forbidden-waiver coverage.

Strict Sphinx build and release build/clean-wheel validation are NOT RUN: they
belong to S14 and S16, and no Sphinx configuration exists yet. The ordinary local
pip installation does build/install a wheel and is separately evidenced; it is
not claimed as release certification. The foundation-only validator is NOT RUN:
it assumes every stage is unimplemented and overwrites its historical artifact.
Linux/macOS, remote CI and independent scientific review are NOT RUN. No scope
was added beyond S12, and no stage is human-accepted.
